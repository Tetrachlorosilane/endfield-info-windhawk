# 行内标记的编译与实例化不变量（原 AGENTS.md §5.1 的标记部分，含 §5.7 的编译管线）

**何时读这个文件**：加一个新标记、改 `[[size:]]` / `[[gap:]]` / 对齐组 / `[[/]]` 的语义，
或动 `CompileRowText` / `InstantiateRowProgram` / `BuildRowLayout` / memo 键之前。

**同读**：[layout.md](layout.md)（行高与框）、[text-measurement.md](text-measurement.md)（预算）、
[fonts.md](fonts.md)（`[[font:]]` 是同一个标记机制的第二个用户）、[icons.md](icons.md)
（`[[icon:]]` 是编译期就变成段的那类元素）。

设计与语法：[../inline-markup-design.md](../inline-markup-design.md)（标签语法、规范化像素计算、迁移顺序）。

## 1. 标记 → 段的编译管线（只编译一次）

- **行内标记在读取设置时编译一次**（`CompileRowText` → `ModSettings::rowProgram[]`，与 `rows[]`
  同一份数据），发布路径只展开 `{变量}` 与环的数值字段（`InstantiateRowProgram`），
  发布期不再解析标签、也不再查链序号。
- **`[[/]]`（不用写名字的收尾）是编译期脱糖，不许让布局或绘制认识它**：
  `CompileRowSuffix` / `InstantiateRowProgram` 各一份**同规则的开块栈**（三种 kind 各最多一帧、
  收尾弹栈顶），标记一律经 `WriteBlockClose`；**memo 键要带开块状态**（只按位置会少标记）。

## 2. `[[gap:…]]`：单位由写法决定，像素上限由位数决定

- 裸数字 = **字号倍数**（`[[gap:1.5]]`，存百分之一 em），带 `px` = **绝对像素**
  （存百分之一像素）；乘字号只发生在 `GapPixels` **一处**，问的是与图标直径同一个
  `ElementFontSizePx`（所以 `[[size:24]]` 里的 gap 和图标一起变大），钳位只在 `ClampGapPx` 一处。
- **上限 99 px**（`kMaxGapPx = 99`）：标记用**四位十进制**写像素的百分之一，
  9999 就是它能写的最大值；写成 512 会让 `(51200 / 1000) % 10` 取到第二位数字，
  于是 100 px 以上的 gap 前两位被换位。**改上限就要同时看 `kGapMarkerMaxValue`。**
- `[[gap:0]]` 合法（零推进，不许变负或 NaN）；读不出来的（`[[gap:]]` / `abc` / 负数 /
  `100px` / `655.36px`）一律**留下原文**。

## 3. 对齐组：标记 + 段上的 `group` 号，不是编译期的树

- `[[left]]`/`[[center]]`/`[[right]]` 在实例化时写成一对标记（开 = 标记+对齐数字+结束符，
  关 = 标记+结束符），`BuildRowLayout` 按位置切成 `TextSeg::group`；`BuildRowPlan` 分三段做：
  **A** 逐元素测量（组内元素以组开头为原点）、**B** 组的宽度（**各部件 `drawnWidth` 之和**）
  与左/中/右定位、**C** 平移到最终 x（**元素也一起平移**，否则预算会拿"组局部"的游标去比
  "面板绝对"的右边缘，`right - x` 变成负数、整段被截没）并按"它不能越过的边"重新拟合组内文字。
  **不嵌套是结构性的**（第二个开标记就是关上一个），所以不需要栈；
  组里只有一层，`AlignGroupPlan` 是 `RowLayoutPlan` 里的定长数组（`kMaxAlignGroups` 10）。
- **"组右边缘"对文字永远不比面板文字列更紧，所以相位 C 的重新拟合是安全冗余。**
  第一遍已经按面板列把每段文字拟合过了，而组的宽度是这些段的宽度之和——
  组不可能比列宽（除非组里有固定尺寸元素，那时整组被夹到列的左边缘）。
  因此真正约束文字的是**列**，`RunBudgetRightEdge`（列与组的较近者）保证的是
  "预算永远来自不能越过的边"这条形状，不是"组一定会截断文字"。
  **不要因为"它反正不会生效"就删掉它**：删了它，一个直接拿自己实测宽度当预算的实现
  （`FitTextToWidth` 第一句就是"放得下吗"，于是恒真）就会把文字画到面板外——负对照实测会红。
- **组比文字列宽时退化成靠左**：夹到列的左边缘，文字各自按列截断，
  固定尺寸元素（图标、环）允许超出——这是刻意的，也是"组内的字符"与"面板边界"冲突时
  唯一不撒谎的取舍。
- **一段文字在组内与组外的宽度可以不同**：相位 C 用组的右边缘（或列）重新拟合，
  所以"同一串字写在组里更短"是正常的，不是 bug。断言用**关系**（右边缘 ≤ 组右边缘/列右边缘）
  而不是硬编码宽度。
- **组内的 run 在相位 A 按"组自己的坐标系"拟合，绝不按行流的游标**（`groupOrigin`）：
  组是整体、在相位 B 才定位的，行流游标对它的落点一无所知。用行流游标曾让
  `[[center]]ABC[[/center]]` 在**前面有一段长读数**时画出 `AB`（再长一个字整组消失），
  而组明明落在面板中间、位置完全正确——因为相位 B/C 只会**缩短** run，那一次截断是永久的。
  断言（前缀 0..40 个 `W` × 三种对齐）：
  `a group's content survives a long flow run before it (all three alignments)`、
  `and the group's width counts the characters the flow run was stealing`。
- **没有组 = `kAlignSegFlow` = 0**（标记里的组号是 1..3，0 空着）。为什么"没有组"不能用 -1、
  以及"会进静态数组的结构体默认值只能是 0"这条量出来的判据，见
  [layout.md](layout.md) 第 3 节——组与 `AlignGroupPlan` 就在那条判据的正中间。

## 4. `[[size:]]` 的身份由位置决定，横跨本文件与 layout.md

`[[size:NN]]` 写在**行首**是**行属性**，写在**别处**是**段属性**（同一个标签、两套用途）。
编码侧（`kSizeMarkStart` + 两位十进制数字 + `kRingMarkEnd` / `kSizeMarkEnd`）在本文件描述；
它对行高与段字号的影响、以及"行首标签只认行首"的容错规矩写在 [layout.md](layout.md) 第 1 节。
两半必须一起读——**改这一条时先确认改的是哪一半**。
