# 多字体与按行尺寸：设计规格

面向**实现者**。用户向说明写在 [README.md](../README.md)，不变量写进
[AGENTS.md](../AGENTS.md)；本文只回答"怎么做、为什么这么做、怎么验证"。

两个需求、两批实现（分开提交，各自带断言）：

* **A 批：字体**——全局回退链 + 按段覆盖，**未配置时零成本**。**已实现**
  （2026-10-14，`test-layout.cpp` 的 "font chains and the multi-font cost gate" 一节，102 条断言；
  实现与本文的差异都记在下面的方框里）。
* **B 批：按行字号与高度**——设置项 + 行首标签两套，标签覆盖设置项。**已实现**
  （2026-10-14，"per-row font size and height" 一节，82 条断言）。
* **C 批（B 批的补充）**：`[[size:…]]` 也支持**段级**（写在别处就是一段），
  以及把图标盘改回"只跟随全局 `Font size`"。**已实现**（同一天，29 条新断言）。

> **A 批落地时与本文不同的三处**（本文已按实现更新，这里留个索引以免"对齐文档"时改回去）：
> 1. `PickFontFamily` 的 `covers` 回调收**族名**而不是族索引（链不同、索引会歧义）；
> 2. 覆盖判定返回**族名指针或 `nullptr`**，而不是"链索引 0 = 主字体"；
> 3. 显式标签的语义分两档：ASCII 段直接用第一个族名（零查询），非 ASCII 段才按顺序问覆盖。
> 另外顺手修掉了同一类的一个老缺陷：画不出来的 `[[ring:…]]` 原本"消费掉但不产出"，
> 会把文字一起从屏幕上删掉，现在同样回退成原文。

> **B 批落地时与本文不同的三处**：
> 1. §5.2 第 2 条说的"命中测试要对每行算上下边界"**不存在**：`WM_NCHITTEST` 只做圆角判定，
>    行从来不是单独的点击目标。真正需要改的是**面板高度**（窗口高度、命中矩形高度、入场目标
>    都来自 `ComputeGeometry`），所以断言打在那里：它必须等于各行高度之和。
> 2. 行高下限用了 `kRowHeightFontSlack = 15`，取的就是默认配置里 `Row height 30` 与
>    `Font size 15` 的差——这样**默认配置的高度逐值不变**，而字号变大时行跟着变大。
> 3. 落地时发现同一层里还有一个真缺陷：留空的行会让后面的**图标**错位（详见
>    [state-and-handover](state-and-handover.md) §13）。修法是给"设置行号 → 发布行序"建一层
>    显式映射（`rowSlotOf[]`），图标、字号、行高三者共用它。

## 1. 为什么不能"总是走多字体通路"

多字体意味着对每段文字做**字形覆盖查询**（`GetGlyphIndicesW`，缺字形返回 `0xFFFF`），再按
(族, 字号) 取字体对象。一条纯 ASCII 行根本不需要这些：任何常见拉丁字体都能画，查一遍纯属浪费，
而面板是**每帧重绘**的（`PaintPanel` 每次重建字体，见 AGENTS §5.1 关于"字体每帧重建"的教训）。

所以本设计的第一条规则是**成本闸门**：

> **只要这行原文没有任何字体配置、且全局回退链为空，就走今天那条路**：一行只按字号建一个字体、
> 所有段共用、**零覆盖查询、零额外分段、零第二字体对象**。

闸门在**配置期**判定一次（`ReadSettings` 扫描原文），不在每帧判定。

## 2. 设置项（A 批）

| 键 | 类型 | 默认 | 说明 |
| :-- | :-- | :-- | :-- |
| `FontFamily` | 字符串 | `Segoe UI` | **已有**。主字体族 |
| `Fallback fonts` | 字符串 | 空 | **新增**（YAML 键 `FallbackFonts`）。分号分隔的候选链，如 `Microsoft YaHei UI;Segoe UI Emoji`。空 = 不回退（等于今天的行为） |

`ModSettings` 增加：一个全局 `FontChain fallbackFonts`（`names[kMaxFontFamilies][kMaxFontFamilyChars]`
+ `count`，上限 4 项、48 字符/项），标签链 `FontTag tagFonts[kMaxFontChains]`（上限 6 条，
每条含**规范文本** `key` + 过滤后的 `chain`），以及**每行一个布尔** `bool rowFontTag[kMaxRows]`
（配置期扫描结果）。

解析规则：去掉首尾空白、跳过空项、大小写不敏感去重、上限 `kMaxFontFamilies`；超出的项丢弃并在
`ReadSettings` 里记一次**有界日志**（不要每帧打）。解析与过滤分成两个函数
（`ParseFontChainList` 纯解析、`FilterChainToInstalled` 查已安装列表），因为过滤要问注册表而
解析不该依赖机器状态——断言因此可以在两种机器上都成立。

## 3. 行内标签（A 批）

```
[[font:族名]]     开始一段（族名可含分号，表示这一段自己的候选链）
[[/font]]         结束这一段（缺省则到行尾结束）
```

语义：段内文字先在**标签给的候选链**里选，再退到**全局回退链**；都不覆盖时退到主字体。
两档细节：ASCII 段直接用标签第一个族名（零查询），非 ASCII 段按顺序问覆盖。

容错（**硬要求**）：拼错、未闭合、族名超过 `kMaxFontFamilyChars`、族名没装、超过
`kMaxFontChains` 条链的标签**当作普通文本绘制**，并记一次有界日志。**绝不允许因为标签问题让整行消失**
——AGENTS §5.1 的第一条教训就是"一行算成 0 宽会让 GDI+ 把整行裁掉"。
落地时这一条抓到过一个真实实现错误：第一版在"链没注册"时也 `p = close + 2`（消费掉标签但不产出
标记），于是 typo 的标签连同文字一起消失——断言 `tag is stripped, text survives` 当场变红。
**判据是"未注册的标签必须原样留在文本里"**，不是"别崩"。

标记机制与现有的 `[[ring:…]]` 完全一致：展开期把标签换成**私用区标记**
（`kFontMarkStart` + 链序号 + `kRingMarkEnd`，结束标记 `kFontMarkEnd`），`BuildRowLayout` 剥掉标记
并给每个 `TextSeg` 带上 `tagChain`。这样"剥标记"只有一处实现，测试与绘制共用。
标签 → 链序号的匹配用**规范文本**（族名按分号重连，见 `FontChainKey`），
所以 `[[font:A ; B]]` 与 `[[font:A;B]]` 是同一条链，而不是两条。

## 4. 绘制侧（A 批）

* **候选选择**是纯函数，覆盖判定**以函数指针注入**（最终签名）：

  ```cpp
  // 返回该段应当使用的族名，或 nullptr 表示用主字体。
  // covers 收族名而不是索引：不同的链可以有同名的项，索引有歧义。
  static const WCHAR *PickFontFamily(const WCHAR *run, int len, const WCHAR *mainFamily,
                                     const FontChain &explicitChain, const FontChain &fallback,
                                     bool (*covers)(const WCHAR *family, WCHAR ch));
  ```

  规则（按顺序）：

  1. 段为空或没有候选 → 主字体（不查询）；
  2. 段内有 **ASCII 以外**的字吗？没有 → 显式链有则用它第一个，否则主字体（**不查询**）；
  3. 显式链：按顺序问覆盖，第一个覆盖全段的胜出；
  4. 全局链（有显式链时是它的后备）：先问**主字体**是否覆盖全段，是就用主字体；
     否则按顺序问全局链；
  5. 都不覆盖 → 主字体。

  断言注入一张假覆盖表 + 一个**查询计数**即可覆盖全部分支，包括"纯 ASCII 段查询次数为 0"
  这条性能承诺（用计数断言，而不是靠注释）。

* **纯 ASCII 段跳过查询**：段内没有 `> 0x7F` 的字符就直接用主字体。这条写进代码注释与 README，
  因为它是性能承诺的一部分（一个全英文面板即使配了回退链也完全不付多字体的代价）。
  量它的现场指标是 `[perf]` 行的 `glyphq=`。

* **覆盖查询缓存**：定长静态表 `{familyHash, ch, covered, used}`，256 槽、线性扫描 + 轮转覆盖，
  **无堆分配**（与 mod 一贯的零分配纪律一致）。未命中才调 `GetGlyphIndicesW`
  （`GGI_MARK_NONEXISTING_GLYPHS`，用一个内存 DC + 按需建/按族缓存的 HFONT）。
  断言用**真实 GDI** 跑一次同族同字的查询：计数第一次 +1、第二次不变。

* **字体对象缓存**：`GpFont*` 按 (族, 字号) 缓存，8 槽，**空槽优先于 LRU**——把"腾出最近的"
  写在"用空槽"前面会让两个字号交替绘制时每帧重建对象（实测由断言抓到）。设置变更时整体释放
  （`ReleaseFontResources`，在 HUD 线程），卸载时在 `GDI+ Shutdown` **之前**释放——
  与图标缓存（`ReleaseSlotImage`/`DisposeIconImage`）同一套路，别各写一套生命周期。

## 5. 按行字号与高度（B 批）

### 5.1 两套载体

| 载体 | 例子 | 优先级 |
| :-- | :-- | :-- |
| 设置项 | `Row 2 font size` / `Row 2 height`（`0` = 继承全局） | 低 |
| 行首标签 | `[[size:18]]` / `[[h:44]]`（**只认行首**，可在文本前连续出现） | 高（覆盖设置项） |

标签放在行首而不是任意位置，是为了不引入"局部行高"这种无法定义的东西：**行高是行的属性**。
`[[size:…]]` 放在行首同时也成为该行**默认字号**，段级字号不在本批范围内。

> **B 批之后的补充（2026-10-14，用户要求）**：段级字号**后来还是做了**——`[[size:NN]]` 写在
> 文本中间（或行首之外的任何位置）就是一段的字号，`[[/size]]` 收尾。落在它头上的两条规矩，
> 和原来"行高是行的属性"并不冲突：
> * **位置决定身份**：行首 = 行属性（`ReadSettings` 剥掉，同时决定该行高度下限）；
>   别处 = 段属性（`kSizeMarkStart` + 两位数字 + `kSizeMarkEnd`，进 `TextSeg::runFontSize`）。
> * **行高下限取"这一行里最大的字"**（`rowMaxFontSize` = 本行字号与 `MaxInlineRunSize` 的较大者），
>   所以段字号变大并不会把字挤出这一行——"行高是行的属性"这条因此仍然成立。
> 同时修掉了 B 批引入的一个错误：**图标盘不再跟随行字号**（用户报"改行 size 后图标也变大"），
> 回到跟随全局 `Font size`。

落地细节：前缀由 `ParseRowMetricTags` 在 `ReadSettings` 里剥掉，`rows[]` 里存的是**不含标签**的文本，
所以标记编译器（`CompileRowText`）与发布期的 `InstantiateRowProgram` 都不知道这两个标签存在。`0`（无论来自设置项还是标签）
都表示"没设"，继续往下继承；同一个标签写两次则后一个生效。

### 5.2 影响面（这就是它必须单独一批的原因）

行高可变会牵动：

1. **面板高度**：`ComputeGeometry` 用 `PanelRowsHeight`（Σ 行高）取代 `rowHeight * rowCount`；
   `RowTopPx` 是逐行前缀和，绘制侧与 `ComputeGeometry` 共用同一对函数。
2. **命中测试**：`WM_NCHITTEST` 只做圆角判定（行从来不是独立点击目标），但它用的
   `g_displayHeight` 就是上面那个和——所以断言打在 `ComputeGeometry` 的输出上。
3. **图标盘与环**：`IconPlateDiameter` 跟随**该行**字号；圆心用 `RowHeightPx(settings, slot)`；
   文字列的左内缩用 `MaxIconPlateDiameter`（列是共享的）。
4. **入场动画**：`g_displayHeight` 的目标高度来自累加结果，收回/展开的关键帧不改（它们只关心
   起止高度），但**测试里那些假设 `rowHeight * n` 的断言要跟着改**（已改：回归护栏先跑默认配置）。
5. **岛上卡片**：与行无关（卡片自己的几何），不动 —— 画片上明确注释了"卡片取全局 `Row height`，
   不受行高影响"，免得下一个人以为漏了。

### 5.3 不变量

* 每行高度 = 该行字号推导出的**最小**高度与配置高度的较大者（字号涨了行不能反而放不下）；
  最小高度 = 字号 + `kRowHeightFontSlack`（15，即默认 30−15），所以**默认配置逐值不变**；
* 面板总高 = Σ 行高（+ 内边距），且**下限**仍是标签高度（收起时不消失）；
* `[[h:…]]` 比 `[[size:…]]` 先解析（行高是行属性，字号只影响内容），两者互不影响；
* 标签只认行首：出现在文本中间的 `[[size:20]]` 当普通文本（**不要**半路改行高）。

## 6. 断言清单（写进 `test-layout.cpp`）

**A 批——已实现，102 条断言落在 "font chains and the multi-font cost gate" 一节**

1. `PickFontFamily`：显式链命中第一个覆盖的族；都不覆盖 → 主字体；空段 → 主字体；
   显式链覆盖不到时退到全局链；全局链也没有 → 主字体；
2. 覆盖查询**次数**：纯 ASCII 段查询次数为 0（用计数器注入），含 CJK 的段按候选顺序查询，
   且**真实覆盖查询**在缓存命中后为 0（`g_coverQueryCount` 前后对比）；
3. **成本闸门**（本设计的核心断言）：`RowNeedsFontPath(rowHasTag, hasGlobalChain)` 的真值表；
   `ReadSettings` 端到端：空设置 + 无标签 → 两行都不需要多字体通路；
4. 标签容错：`[[font:]]`、`[[fonts:…]]`（拼错）、缺 `]]`、未安装族名、超过 6 条链 —— 
   全部**留下原文**，并且"每个可见字符都属于某个段"（防止"标签吃掉整行"）；
5. 设置解析：分号列表 → 项数/内容/规范文本；全空 → 计数 0（闸门因此关闭）；
   未安装的项被丢弃且计数；
6. 端到端（展开 + 剥标记）：`CPU 12%` 的段归属（带标签的段 `tagChain=1`、其余 0）；
   一行内多段换字体；`[[/font]]` 之后的文字回到主字体；
7. 字体对象缓存：同族同字号两次拿到同一对象、不同字号是不同对象、释放后缓存为空。

**B 批——已实现，82 条断言落在 "per-row font size and height" 一节**

8. 行高解析：`ParseRowMetricTags` 的 17 个用例（两种标签、顺序无关、重复覆盖、`[[h:0]]`、
   以及**七种必须留下原文**的写法：中间标签、`abc`、空值、缺 `]]`、带空格、`height:`、超范围）；
9. `RowFontSizePx` / `RowHeightPx`：0 继承、逐行覆盖、**下限随该行字号**、
   默认配置 `MinimumRowHeightForFont(15) == 30`（默认外观不变的护栏）；
10. 面板总高 = Σ 行高，行顶 = 前缀和，相邻行**不重叠**，`PanelRowsHeight(n) == RowTopPx(n)`；
    默认配置下高度与行顶**逐值等于** `rowHeight × n` / `r × rowHeight`；
11. `ComputeGeometry` 真的用了那个和（把 `PanelRowsHeight` 换成乘法，这条必须变红）；
12. `ReadSettings` 端到端：标签剥离、标签覆盖设置项、越界钳位、留空行的行号映射；
13. 图标盘：大字号行拿到大盘，共享内缩按**最宽**的盘算。
